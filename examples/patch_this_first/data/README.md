# Data

All data used by the app is public. The user's pasted software list is matched in memory and is never written to disk, logged or sent to an AI service.

## Sources

| Source | File | Licence | Credit shown in the app |
|---|---|---|---|
| CISA Known Exploited Vulnerabilities (KEV) catalog, `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json` | `raw/kev.json` (downloaded, not committed) | CC0 1.0 | "CISA Known Exploited Vulnerabilities Catalog (CC0 1.0), version <catalogVersion>" |
| FIRST EPSS API, `https://api.first.org/data/v1/epss` | `processed/epss.json` (cache: scores for every KEV CVE, refreshed once a day) | Free to use; attribution requested in publications and products (FIRST EPSS FAQ) | "EPSS scores from FIRST.org (first.org/epss), dated <score date>" |

No CISA or FIRST logo is used, and nothing in the app implies endorsement by either organisation.

## Folders

- `raw/`: downloaded files. Gitignored; regenerated by the app on start (`core/fetch.py`). If a download fails, the app uses the last saved copy and shows its date.
- `processed/`: caches derived only from public data (EPSS scores, cached example AI text for the sample list). Can be committed.
- `samples/`: invented example software lists, labelled as such. Not any real organisation's list.

## Processing

- KEV: downloaded as-is; the app checks it has `catalogVersion` and a `vulnerabilities` list, and drops entries without a `cveID` (logged).
- EPSS: scores are fetched for **every** KEV CVE (not only the ones a user's list matches), so neither the cache nor the requests to FIRST depend on, or reveal, anyone's inventory. Scores outside 0–1 are dropped (logged). If the API is down, the last cache is used; with no cache, ranking uses KEV fields only.
- Matching (`core/match.py`) and ranking (`core/rules.py`) run in memory on the pasted list; see the docstrings and `PROGRESS.md` for the rules.
